## 1. 角色（硬）

| 角色 | 谁 | 做 | 不做 |
|------|-----|-----|------|
| **总控** | Grok（本对话/规划窗） | 定优先级、切窗、写任务书、审查、合 main 门禁、夜间/日间节奏 | 不把执行细节甩给业主；不自 PASS 产品终局 |
| **执行** | Codex | 按任务书改代码、测、PR、部署生产、贴证据 | 不改 edu-cloud；不升 v1.3 无授权；不另立真源 |
| **业主** | 你 | 拍板、授权 M5、公网一眼、开新 Codex 窗贴任务书 | 不负责写实现细节 |

**规划时必须默认：总控不写生产热更；执行窗有服务器与浏览器。**  
总控可并行：审查、文档法条、不与执行 lease 冲突的小 PR。

## 2. 日间任务（总控怎么派）

- **短、可验收、可并行**：1 个主目标 + 明确完成定义。  
- **语言**：任务书 / 派工，**不要**默认叫「夜卡」。  
- **体量**：预计 Codex **0.5～2h** 有效；更大则拆或标「加厚日间」。  
- **交付**：PR + CI +（若动运行时）DEPLOYED + 固定报告头。

## 3. 夜间任务（总控怎么派 · 硬约束）

夜间派工 **必须** 满足：

| 要求 | 说明 |
|------|------|
| **打满约 6h** | 多任务包 或 单轨深挖+强制加厚包；禁止「一个最小闭环就收工」 |
| **多任务 / 长任务** | 至少 **主目标 + ≥3 强制包**（或等价工作量） |
| **可控风险** | 允许大 UI、矩阵、CI e2e、Skill 扩、模块整理；PR 写 `RISK:` |
| **禁止早停** | 强制包未完成或未书面 BLOCKED 不得交卷；建议报告 `hours used` |
| **部署** | 动运行时则夜末 DEPLOYED；纯文档例外 |
| **HARD 不变** | 只 pico；禁 edu-cloud 写；禁 PROXY=1；禁公网 18765/27017/8080；禁打印 key |

夜间模板见 `docs/NIGHT-CARD-POLICY.md`（策略）+ 当次任务书（总控新拟或更新卡）。

**文件名可含 NIGHT，但总控口述应区分「日间任务书」vs「夜间长任务书」。**

## 4. 总控规划检查单（发任务前自检）

```text
□ 执行者是 Codex（有 VPS/浏览器），不是业主本机
□ 日间 vs 夜间已标明
□ 若夜间：能否撑满 ~6h？是否多包/有风险包？
□ LEASES 是否与并行窗冲突
□ 完成定义是否可在 GitHub 验证
□ HARD / 非目标是否写清
□ 审查门禁：谁合 main（总控或授权执行合）
```
