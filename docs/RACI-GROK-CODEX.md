```

```

## 1. 角色（硬）

| 角色 | 谁 | 做 | 不做 |
|------|-----|-----|------|
| **总控** | Grok（本对话/规划窗） | 定优先级、切窗、写任务书、审查、合 main 门禁、夜间/日间节奏 | 不把执行细节甩给业主；不自 PASS 产品终局 |
| **执行** | Codex | 按任务书改代码、测、PR、部署生产、贴证据 | 不改 edu-cloud；不升 v1.3 无授权；不另立真源 |
| **业主** | 你 | 拍板、授权 M5、公网一眼、开新 Codex 窗贴任务书 | 不负责写实现细节 |

**规划时必须默认：总控不写生产热更；执行窗有服务器与浏览器。**  
总控可并行：审查、文档法条、不与执行 lease 冲突的小 PR。

## 2. 日间任务（总控怎么派）

- **短、可验收**：单窗 1 个主目标 + 明确完成定义。  
- **语言**：任务书 / 派工，**不要**默认叫「夜卡」。  
- **体量**：单窗预计 Codex **0.5～2h** 有效；更大则拆或标「加厚日间」。  
- **交付**：PR + CI +（若动运行时）DEPLOYED + 固定报告头。

### 2.1 日间并行（硬：能并行则并行）

总控规划日间时 **必须主动拆并行轨**，不要默认串成一条队。

| 原则 | 说明 |
|------|------|
| **默认并行** | 无文件/语义冲突的工作同时派（多 Codex 窗或多个短 PR） |
| **路径隔离** | 每轨写清可写路径 / 禁止路径（lease）；共享文件指定单写窗或 WAIT |
| **合流点最少** | 仅 principal / Task / Change / 发布 等硬汇合；其余互不锁 |
| **证据也并行** | 一轨实现时，另一轨可只读测、矩阵、文档、selftest |
| **总控自留并行** | 审查、法条文档、不撞 lease 的小 PR 可与 Codex 执行并行 |
| **不能假并行** | 同文件双写、未 rebase 的双 PR 乱序 → 总控串行化并说明原因 |

**日间典型并行组合（示例）：**

```text
窗 A（Codex）：LibreChat UI / 能力中心
窗 B（Codex 或总控）：API 测 / skill_policy / selftest
窗 C（只读）：矩阵截图、PR 审查、M5 文档勾选
```

**单 Codex 时的「逻辑并行」：**  
同一执行窗内用时间片切换多包，但任务书仍列出 **可并行包清单**；有第二窗立即拆窗。

**总控发日间任务前追加自检：**

```text
□ 是否已标「可并行轨」与 lease？
□ 若只能串行，原因是否写明（冲突文件/发布锁）？
□ 总控是否同时接审查或非冲突小任务？
```

## 3. 夜间任务（总控怎么派 · 硬约束）

夜间派工 **必须** 满足：

| 要求 | 说明 |
|------|------|
| **打满约 6h** | 多任务包 或 单轨深挖+强制加厚包；禁止「一个最小闭环就收工」 |
| **多任务 / 长任务** | 至少 **主目标 + ≥3 强制包**（或等价工作量） |
| **可控风险** | 允许大 UI、矩阵、CI e2e、Skill 扩、模块整理；PR 写 `RISK:` |
| **禁止早停** | 强制包未完成或未书面 BLOCKED 不得交卷；建议报告 `hours used` |
| **部署** | 动运行时则夜末 DEPLOYED；纯文档例外 |
| **HARD 不变** | 只 pico；禁 edu-cloud 写；禁 PROXY=1；禁公网 18765/27017/8080；禁打印 key |

夜间模板见 `docs/NIGHT-CARD-POLICY.md`（策略）+ 当次任务书（总控新拟或更新卡）。

**文件名可含 NIGHT，但总控口述应区分「日间任务书」vs「夜间长任务书」。**

## 4. 总控规划检查单（发任务前自检）

```text
□ 执行者是 Codex（有 VPS/浏览器），不是业主本机
□ 日间 vs 夜间已标明
□ 若日间：可并行轨是否已拆？lease 是否写清？
□ 若夜间：能否撑满 ~6h？是否多包/有风险包？
□ LEASES 是否与并行窗冲突
□ 完成定义是否可在 GitHub 验证
□ HARD / 非目标是否写清
□ 审查门禁：谁合 main（总控或授权执行合）
```
