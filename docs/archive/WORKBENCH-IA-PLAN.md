## 2. 调研结论：WorkBuddy 功能逻辑（抽象，非实现）

### 2.1 产品一句话

不是「再做一个聊天框」，而是：

> **接收工作目标 → 组织上下文 → 规划 → 调能力执行 → 产出可验收物 → 用户验收/迭代**

### 2.2 六层运行模型（公开归纳）

```text
① 任务入口     桌面输入 / 文件截图 / IM / 定时
② 上下文       Task · Workspace · Project · Memory
③ 编排推理     理解 → 拆解 → 专家/多 Agent → 自检
④ 执行能力     Skill · Connector · MCP · 本地/工具
⑤ 交付         产物 · 文件变更 · 预览 · 分享
⑥ 治理         最小权限 · 高风险确认 · 审计
```

### 2.3 核心对象词典

| 对象 | 含义 | 对 Pico 的含义 |
|------|------|----------------|
| **Task** | 一次目标驱动的工作会话（有状态机） | ≈ Conversation + Pico `Task`/`Run` 账本 |
| **Workspace** | 本次任务的文件边界与产物目录 | 浏览器：会话附件 + 产物存储；桌面目录后置 |
| **Project** | 团队级规则/资料/能力注入容器 | LibreChat Projects + 后续「项目指令」 |
| **Memory** | 跨任务个人偏好 | LibreChat Memories |
| **Expert / 助理** | 角色化 Agent（方法论 + 工具倾向） | Agents / 市场 |
| **Skill** | 可复用流程/动作包（会「干活」） | Skills |
| **Connector / MCP** | 接外部系统的统一协议 | MCP Servers |
| **Automation** | 定时/周期任务 | **后置**（Phase 非必须） |
| **结果区** | 概览 / 产物 / 文件树 / 变更 | **最大体验差**；需 UI 层补 |

### 2.4 信息架构（公开 UI）

**首页（业主截图）**

- 左：新建任务 · 助理 · 项目 · 专家·技能·连接器 · 自动化 · 空间  
- 中：`{产品}, 我帮你` + 场景 tabs（日常办公 / 代码 / 设计）+ 能力 chips + 大输入框  
- 输入辅助：工作空间 · 权限 · 模型 Auto · @ 文件 · / 技能  

**任务进行中（公开教程）**

| 区 | 职责 |
|----|------|
| 左 | 任务列表（最近 / 按空间）、状态筛选 |
| 中 | 任务对话 + 进度 + 停止 + 追问 |
| 右 | **结果区**：概览 · 产物 · 全部文件 · 变更 |

### 2.5 完整任务闭环（示例：经营分析报告）

```text
用户提交目标+数据
  → 创建 Task（+ Workspace 边界）
  → 读上下文 / 项目规则 / Memory
  → 规划步骤（清洗→分析→图表→结论→PPT）
  → 调 Skill / 工具 / MCP
  → 写产物到结果区
  → 用户验收 / 追问迭代 / 归档
```

### 2.6 与「纯 Chat」的本质差

| 纯 Chat | 任务工作台 |
|---------|------------|
| 消息流为主 | **任务状态 + 产物**为主 |
| 结束 = 最后一条回复 | 结束 = 可下载/可预览交付物 |
| 工具偶尔出现 | 工具/技能是一等公民 |
| 无文件边界 | Workspace 是安全与效率边界 |
| 无验收面 | 右侧结果区 = 验收面 |

## 3. Pico / LibreChat 现状对照

### 3.1 已具备（可映射，勿重复造）

| WorkBuddy 概念 | 现状 | 成熟度 |
|----------------|------|--------|
| 对话 / 任务会话 | LibreChat conversation + Pico Task/Run | 中（账本在 Pico，UI 仍偏 Chat） |
| 真模型流式 | Kimi API + `/v1/chat/completions` | **高**（S1 已通密钥） |
| Agent 多步环 | `pico_orchestrator.runner` | 中（工具白名单紧） |
| 助理 / 专家 | Agents + Marketplace | 中（需 IA 改名与入口） |
| 项目 | Projects | 中（侧栏已有） |
| 技能 | Skills | 中 |
| 连接器 | MCP | 中（空状态已中文） |
| 记忆 | Memories | 中 |
| 提示词 | Prompts | 中（可并入「专家方法」心智） |
| 产物雏形 | Artifacts / 附件 | 低～中（无独立「结果区」） |
| 中文 + Pico 品牌 | 登录/首页已推进 | 中 |

### 3.2 缺口（体验差最大处）

| 缺口 | 说明 | 优先级 |
|------|------|--------|
| **G1 首页心智** | 仍是「下午好 + Chat」不是「Pico，我帮你 + 场景任务入口」 | P0 |
| **G2 侧栏 IA 命名** | 对话记录 / MCP 设置等偏工具名，不像任务台 | P0 |
| **G3 结果区** | 无右栏：产物 / 文件 / 变更 | P1 |
| **G4 任务状态机 UI** | 规划中/进行中/完成 未暴露 | P1 |
| **G5 Workspace 边界** | 无「本次任务工作目录」选择（浏览器用附件集模拟） | P1 |
| **G6 自动化** | 无定时任务 | P2 后置 |
| **G7 远程 IM 助理** | 无企微/微信遥控桌面 | **不做**（桌面专属） |
| **G8 本地全盘文件 Agent** | 与沙箱/浏览器产品形态不符 | **不做**（Phase1） |
| **G9 账本双写** | LibreChat Mongo vs Pico SQLite | 架构债：事件以 Pico 为准 |

### 3.3 形态差（必须写进计划）

WorkBuddy = **桌面 Agent Runtime**（本地文件 + 权限确认）。  
Pico Phase1 = **浏览器工作台** + 服务端 Agent + 模型 HTTPS。

因此：

- **借鉴：** 任务入口、对象分层、结果交付、技能/连接器心智  
- **不借鉴：** 桌面安装、本地 Shell 默开、IM 遥控电脑  

---

## 4. 目标体验（Pico 自己的定义）

> **Pico = 学校场景可用的 AI 任务工作台**  
> 用户用自然语言提出任务 → 服务端 Agent（Kimi）规划执行 → 产物在界面可验收 → 全程记入 Pico AI 账本。

非目标：腾讯办公生态连接器、桌面远程、抄 WorkBuddy 视觉。

---

## 5. 实施规划（分阶段）

### 原则

1. **只改 `apps/librechat` 魔改 + Pico API**，不新壳。  
2. **先 IA / 心智，再结果区，再自动化。**  
3. 每阶段可演示；不自 PASS；CANDIDATE → CI → 审查。  
4. 不升 MVP v1.2 文档版本，本规划为 **S5 产品打磨子计划**。

---

### Phase A — 心智对齐（约 0.5–1 天）· **先做**

**目标：** 打开产品就像「任务台」，不再像通用 Chat 皮肤。

| 项 | 做法 | 验收 |
|----|------|------|
| A1 首页 | Landing：`Pico，我帮你` + 场景 tabs（日常办公/教学教研/代码开发 等校本化）+ 能力 chips 写入输入框 | 新对话页截图无「ChatGPT 空问候」感 |
| A2 输入文案 | 占位：`今天帮你做什么？可用 @ 引用文件，/ 调用技能` | 中文、任务向 |
| A3 侧栏命名 | 新建任务 / 任务 / 助理 / 项目 / 技能 / 连接器 / 记忆（i18n，不改路由也可） | 一级名词与截图品类对齐 |
| A4 去品牌 | 页脚/关于/标题已 Pico；扫残留 LibreChat | 用户可见无 LibreChat 主品牌 |
| A5 浅色工作台气质 | CSS token：浅灰底、圆角大输入、弱阴影（非 1:1 抄皮肤） | 明亮任务台，非纯黑 Chat |

**不做：** 右栏结果区、自动化、桌面权限。

---

### Phase B — 任务与列表（约 1 天）

| 项 | 做法 | 验收 |
|----|------|------|
| B1 任务列表心智 | 对话列表展示状态徽章（进行中/失败/完成）——数据来自 Pico Run 若可拉，否则先本地会话 meta | 列表不像纯标题堆 |
| B2 项目注入 | 在 Project 内新任务显示项目 chip；后续支持项目级 system 指令 | 项目内开聊有上下文提示 |
| B3 停止/追问 | 已有 stop + 流式；文案改为任务向（「停止任务」） | 生成中可停 |

---

### Phase C — 结果区 MVP（约 1–2 天）· **体验跃迁**

| 项 | 做法 | 验收 |
|----|------|------|
| C1 右栏面板 | 任务进行中可开关「产物」侧栏 | 三栏雏形：任务列表 \| 对话 \| 产物 |
| C2 产物列表 | 聚合本会话：Artifacts、附件、工具输出文件 | 至少列表 + 下载/预览 |
| C3 与账本 | Pico `Artifact` / Run Event 可查询并展示 | 刷新不丢关键产物元数据 |
| C4 变更摘要（简） | 工具调用时间线（非 Git diff 全盘） | 「本次做了什么」可读 |

**浏览器限制：** 无本地目录树全盘；用「会话工作区文件」代替 Workspace 目录。

---

### Phase D — 能力与编排（并行 / 随后）

| 项 | 做法 | 验收 |
|----|------|------|
| D1 技能入口 | 首页 chips 与 `/` 技能命令打通 | 一点即填提示或挂 skill |
| D2 MCP | 连接器面板保持；空状态引导 | 可加 MCP |
| D3 Agent | 「助理」入口到市场/构建器；校本专家模板后置 | 能选助理开任务 |
| D4 工具白名单 | 保持安全默认；按 S6 扩 ≥2 校场景工具 | 不静默写业务 |

---

### Phase E — 后置（明确不做进当前窗除非授权）

- 定时自动化  
- 微信/企微远程桌面  
- 本地 Shell/全盘文件默认开  
- edu 真联调  
- 换 Chat-UI 壳

## 6. 推荐实施顺序（本窗建议）

```text
1) Phase A（心智）     ← 下一刀实现
2) Phase B（列表状态）
3) Phase C（结果区 MVP）← 与 WorkBuddy 体验差收敛的关键
4) Phase D 按需插空
5) 预览回归 + 中文扫尾 + Kimi 真聊验收
```

**依赖：**

- Kimi 密钥已在服务端 `.env`（勿提交）  
- 预览仍钉 LibreChat `:8080`；白屏先查 Preview 层（见 `PREVIEW-WHITE-SCREEN.md`）

## 7. 成功标准（本规划）

| ID | 标准 |
|----|------|
| W1 | 新用户 10 秒内理解「这是任务工作台」不是通用 Chat 壳 |
| W2 | 侧栏一级名词完成任务台映射（中文） |
| W3 | 首页场景 + chips 能发起真实 Kimi 流式任务 |
| W4 | （Phase C）任意一次工具/附件任务后，产物在固定区域可见 |
| W5 | 无 LibreChat 主品牌；无 WorkBuddy 商标/素材 |
| W6 | `npm` 构建可通过；不双 AI 真源 |
