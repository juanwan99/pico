## 0. 人类视角验收铁律（BINDING · 高于一切机读绿）

```text
验收人是「会点会看会下载的真人」，不是 LLM，不是单测绿，不是 JSON 字段齐。
机器能解析、工具返回 ok、源码「理论上可跑」——单独都不构成 PASS。
```

### 0.1 总原则

| 原则 | 含义 |
|------|------|
| **人用得上** | 打开/下载后，人类能直接使用，不必再破译一堆半成品 |
| **人看得懂** | 文档有标题结构与可读正文；不是 token 墙、不是仅对模型友好的裸日志 |
| **人点得动** | HTML/小工具：真人浏览器打开有界面与反馈，不是丢一坨源码交差 |
| **人分得清** | 多文件：文件名/类型能区分用途；不是同文复制四份 |
| **人信得过** | 声称可运行/已验证必须对应真人路径证据；否则写明未验证 |

### 0.2 分类型人类门槛（一律适用）

| 类型 | 人类 PASS | 人类 FAIL（典型） |
|------|-----------|-------------------|
| **HTML / 前端** | 双击或浏览器打开即见可用 UI；主按钮有反馈；说明如何打开 | 只交 `.html` 源码墙、白屏、要点控制台才懂、无界面 |
| **Word/PDF/MD 文稿** | 打开即有标题/段落/可读中文；打印或转发不丢人 | 乱码、半截、纯 bullet 无结构、机器摘要冒充正文 |
| **表格/排班类** | 人眼能扫懂列含义与行列 | 无表头、乱列、不可辨 |
| **PPT** | 翻页有要点，投影可读 | 空白页、字号飞掉、仅大纲一页糊弄 |
| **图片** | 打开即见图；与任务相关 | 破图、0 字节、文不对题 |
| **压缩包/多文件** | 解压后人类能按名找到用途 | 单文件冒充、空包、文件名全 `output_1` |
| **自检报告** | 人能读懂验了什么、没验什么 | 「全部完美」无步骤；只有 LLM 自评 |

### 0.3 证据要求（人类视角）

| 可采信 | 不可单独采信 |
|--------|----------------|
| 真人/测试员 **打开后** 截图（可见 UI/正文） | 仅 `artifact id` / 工具 ok |
| 下载后本地打开描述（文件名+看见了什么） | 仅单测 PASS |
| 明确写「未在浏览器点过」且不装成功 | 「结构 valid ⇒ 人类可用」 |

### 0.4 否决（人类视角）

| ID | 否决 |
|----|------|
| **H-FAIL** | 机读/单测/脚本绿，但人类打开不能用或不堪用 |
| **H-CODEDUMP** | 以「源码正确」代替「界面可用」 |
| **H-LLM** | 用模型自述「我已验证」代替人类路径证据 |

**任一切片公网题命中 H-FAIL / H-CODEDUMP → 该切片不得 EXCELLENT。**
