## 1. 宏观目标（背下来 · 不可再偏）

### 1.1 产品是什么

| 项 | 定义 |
|----|------|
| **品类** | 类 **WorkBuddy / Codex / Grok / Kimi / DeepSeek 网页** 的 **任务型 AI 工作台（Web）** |
| **形态** | 浏览器登录即用；**不是**桌面 1:1 克隆，**不是**教务 SaaS，**不是**场景应用超市 |
| **成功** | 人用自然语言 **派活 → 多步执行 → 真交件 → 同会话可改 → 能停能找回 → 状态诚实** |
| **能力** | **通用、开放域**；举例（编程/分析/公文/表…）是样例，**不是**封闭菜单 = 产品 |
| **教育** | 仅领域之一；edu-core **只读后置**；**禁止** Agent 写业务库 |

### 1.2 WorkBuddy 程度 = 六条硬标准（Web 行为）

| # | 标准 | 用户必须感知 |
|---|------|----------------|
| **1** | 开放派活 | 任意自然语言开干，不先锁死场景卡 |
| **2** | 用户侧能力架 | 能看见并选用 Skill / 工具 / 文件等（**不是**纯黑盒客服） |
| **3** | 多步执行 | 真工具环（编排核），不是单轮闲聊冒充 Agent |
| **4** | 真产物 | 要文件则可下可开；短答不硬塞文件；**禁空成功** |
| **5** | 任务资产 | 历史/任务可点回；同会话续聊改一版 |
| **6** | 完成态 | 过程或摘要可见；产物有固定露出（列表/卡片/区） |

**明确不纳入「程度」必达（本期）：**

- WorkBuddy 桌面 exe / 本地 workDir 顶格  
- 像素 1:1、拆闭源  
- 企业 Admin 全套、自动化大盘一次做完  
- 自研 MCP 协议栈 / 自研向量数据库内核  

### 1.3 怎样才算「做成了」（宏观验收）

同一默认入口，**开放域**任务（含当场拟题，非背题卷）：

1. 接得住（通用）  
2. 做得完（多步/工具）  
3. 交得出（真产物或干净短答）  
4. 改得动（同会话）  
5. 选得了（至少若干 Skill/工具前台可选）  
6. 找得回（历史/Run）  
7. 失败诚实  

**禁止：** 用「固定 Word/公号/G1–G7 卷全绿」或「运维/证书 CLAIM」冒充 WorkBuddy 程度完成。

## 2. 架构方案（业主拍板 · 2026-08-06）

### 2.1 选定方案

```text
目标：Web 上 WorkBuddy 程度（六条）
方案：回 Pico 整车 + 默认编排核 Pi + DeepSeek
不做：Dify 门脸终局、场景考卷当对标、双核并列真源
```

### 2.2 分层（干净 B）

```text
┌─────────────────────────────────────────────────────┐
│  门脸（产品 UI）                                      │
│  Pico · apps/librechat（MIT 工作台壳）                 │
│  会话历史 · 大输入 · 流式 · 任务/过程/产物露出         │
└──────────────────────────┬──────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────┐
│  控制面 + 唯一 AI 账本（Pico）                         │
│  Task / Run / Event / Artifact / 取消·重试·权限        │
│  禁止第二套长期 AI 业务真源（含 Dify 会话冒充真源）      │
└──────────────────────────┬──────────────────────────┘
                           │ 唯一 multi-step 入口
┌──────────────────────────▼──────────────────────────┐
│  编排核（默认唯一）= Pi（极简可魔改 Agent harness）     │
│  模型 = DeepSeek HTTPS API                            │
│  Skill / 扩展 = Pi skills·packages + Pico 上架/白名单   │
│  MCP = 接入现成，不自研协议栈（分期）                   │
│  知识库 = Pico 控制面 + 现成检索组件（分期，不自研内核）  │
└─────────────────────────────────────────────────────┘
```

### 2.3 默认编排核 = Pi

| 项 | 决定 |
|----|------|
| **默认核** | **Pi**（业主在用；极简；模型越强壳越赚） |
| **模型** | **DeepSeek** 为主（产品对外脑力） |
| **Reasonix** | **不**并列真源；若实验须 flag，不得写「唯一目标」 |
| **Kimi Agent** | 仓内已有 ENGINEERING 路径 = **遗产/可选回滚**，**不再**作为产品唯一目标 |
| **自研 agent loop** | **禁止**复活为产品目标（历史债，已删逻辑不回流） |

**Pi 职责：** 多步工具环、可扩展 skills。  
**Pico 职责：** 门脸、账本、权限、取消、产物元数据、用户能力架露出。  
**不要求** Pi 单独变成 WorkBuddy；**整车**才是。

### 2.4 能力层（降恐惧 · 分期）

| 能力 | 做法 | 期 |
|------|------|-----|
| 通用对话 + 多步 | Pico + Pi + DeepSeek | **P0** |
| 真产物 | Artifact 下载/展示；交件纪律 | **P0** |
| 用户侧 Skill（≥3 可见可选） | Pi skills + 前台选用 | **P1** |
| 上传文件再问 | 门脸 + 核/检索 | **P1** |
| 知识库 | 现成 RAG，不自研内核 | **P2** |
| MCP | 白名单接入 1～2 个 | **P2** |
| 自动化 | 后置 | **P3** |

**没信心自研 MCP/Skill/KB 内核 = 正确；本期只做接入与上架。**

## 3. 明确不做（禁区）

| 禁 | 原因 |
|----|------|
| **Dify 门脸终局** | 发布 Chat / 默认壳 ≠ WorkBuddy 类产品；Dify 最多过渡工具/RAG 后端 |

| **拆闭源 WorkBuddy / 像素 1:1** | 违法且无必要 |
| **教育专家站主叙事** | 已正本清源作废 |
| **Agent 写成绩/教务库** | 铁律 |
| **密钥进仓 / 假绿 CLAIM** | 铁律 |
| **把实现债写成产品目标** | 历史污染禁止重演 |
