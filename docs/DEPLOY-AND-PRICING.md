## 0. 先锁死的产品事实（不可因收费改坏）

| 事实 | 含义 |
|------|------|
| Pico = **AI 底座** | 对话 + Agent 编排 + 产物 + **唯一 AI 账本** |
| 业务真源在 **edu** | 人/班/权限不进 Pico 当主库 |
| 模型默认 **HTTPS API** | 主成本是 token，不是 GPU 机房 |
| 租户键 = **`school_id`** | 用户是校内成员 `membership_id`，不是「一人一机」 |
| 危险工具默认关 | Shell/File/Web/MCP 不因「好卖」默认打开 |
| 禁止双 AI 账本 | 一校同时跑 edu 旧 AI + Pico 会乱账 |

## 1. 部署：三种可选形态

### 形态 A — 全共享多租户（逻辑隔离）

```text
1 套 Pico 集群（可多副本）
  ├─ school-a 教师…
  ├─ school-b 教师…
  └─ school-n …
DB / 对象存储：行级 school_id 隔离
```

| 优点 | 缺点 |
|------|------|
| 成本最低、升级一次全网 | 强合规客户难接受「和别人同库」 |
| 运维编制最小 | 吵闹邻居：一校打满影响别校（靠配额缓解） |
| 迭代最快 | 售卖话术弱于「专属环境」 |

**适合：** 多数中小校、要快速铺 10 校。

---

### 形态 B — 一校一单元（你倾向的方向）

```text
学校 = 部署单元（1 VM / 1 小主机 / 1 命名空间）
  └─ 该校全部教师 = 应用内租户（成员）
教师 ≠ 虚拟机
```

| 优点 | 缺点 |
|------|------|
| 故障域、数据域按校切开 | 10 校 = 10 套升级/备份/证书（必须自动化） |
| 采购/验收好讲「校级环境」 | 固定成本高于 A |
| 可校级 BYOK、校级网络策略 | 若再做成「人机」则成本爆炸（禁止） |

**适合：** 10 校可管；强调隔离与商务；与「用户是租户、学校是机器」叙事一致。

**单元里跑什么（建议最小镜像）：**

- Pico API + 编排  
- Web（NextChat 或后续壳）  
- 本校 AI 账本 DB  
- **不**默认跑大模型 GPU（仍调 Kimi API）  
- 可选：侧车用量上报 → 总控

---

### 形态 C — 混合（推荐作为正式策略）

```text
默认：形态 A（共享）
签约/合规/大校：形态 B（校级专属单元）
价格与 SLA 用「部署档」区分，代码同一套
```

| 档 | 部署 | 售卖名示例 |
|----|------|------------|
| Standard | 共享多租户 | 标准版 |
| Dedicated | 一校一 VM/主机 | 专属版 |
|（远期）| 客户 VPC / 私有化整包 | 私有化 |

**同一二进制、同一合同字段、`school_id` 语义不变**——变的是「这校的数据落在哪套基础设施」。

## 2. 部署决策建议（请业主圈选）

| 编号 | 决策项 | 建议默认 | 备选 |
|------|--------|----------|------|
| D1 | 默认形态 | **C 混合：标准=共享，专属=一校一单元** | 全面 B |
| D2 | 专属单元粒度 | **一校一单元** | 一集团一单元 |
| D3 | 单元内用户 | **多教师共享，成员级租户** | 禁止一教师一机 |
| D4 | 模型位置 | **API（Kimi 等）** | 校内部署模型另报价 |
| D5 | 密钥 | **平台统一 Key + 计量**；专属可 **校级 BYOK** | 仅 BYOK |
| D6 | 发布 | **不可变镜像 + 舰队滚动** | 禁止 SSH 手改生产 |
| D7 | 数据 | 专属单元 DB 可驻留该单元；备份策略按校 | 共享库逻辑隔离 |
| D8 | 与 edu | edu 可共享或按校；**凭证由 edu 或约定签发方签发** | Pico 自建人事（否） |

### 10 校 × 100 教师的具体建议

1. **前 3～5 校：形态 A** 把产品跑顺、配额与审计跑通。  
2. **有「必须专属」的校：开形态 B**，同一版本镜像。  
3. **总控（你侧）**：清单式管理 10 单元——版本、健康、token 消耗、证书到期。  
4. **绝不**按 1000 教师开 1000 环境。

## 3. 收费：必须拆开的三笔钱

客户感知常常混在一起，**账上必须拆开**，否则要么亏在 token，要么不敢开功能。

```text
① 平台/席位费     → 覆盖研发、控制面、支持、专属机固定成本
② 模型用量费     → 按 token（可转嫁官方价 + 服务费）
③ 可选：专属/私有化/增值工具 → 高隔离与人工
```

### 3.1 计费维度（推荐组合）

| 维度 | 计什么 | 说明 |
|------|--------|------|
| **校** | 基础年费/月费 | 「开一校」的门槛 |
| **席位** | 活跃教师数或授权教师数 | 100 教师/校好报价 |
| **用量** | token（输入+输出）或「千次对话」 | 防滥用；可给校包月包量 |
| **部署档** | Standard / Dedicated 差价 | 专属机收固定加价 |
| **增值** | 高级模型、长上下文、沙箱执行、优先支持 | 功能开关 |

### 3.2 三种可落地的包装（选一种作主报价）

#### 包装 P1 —「校费 + 席位 + 用量」（推荐主方案）

```text
年费 = 学校基础费
     + 席位费 × 授权教师数
     + max(0, 实际 token - 含内包量) × 单价
     + 专属部署加价（若 Dedicated）
```

- **好卖：** 像办公套件 + 电话费  
- **好控：** 包量内可预期，超了有刹车  
- **实现：** 账本已有 Run/Event，可聚合成校级用量

#### 包装 P2 —「纯包月包量」

```text
一校一档：例如 100 席 + N 百万 token / 月，超额停或降级
```

- **好卖：** 预算制学校喜欢  
- **风险：** 重度校吃垮包量 → 必须监控与阶梯  

#### 包装 P3 —「平台费 + 全额用量转嫁」

```text
低年费 + token 按官方价 × (1+服务费率)
```

- **稳健：** 模型涨价可跟  
- **难卖：** 学校厌恶不可预测账单 → 需账单上限/预警  

### 3.3 建议默认报价结构（数字仅作结构示例，非最终价）

> 下列数字用于 **结构讨论**，不是对外报价承诺。

| 项 | Standard（共享） | Dedicated（一校一机） |
|----|------------------|------------------------|
| 学校年费 | 低～中 | 中 + **专属资源年费** |
| 席位 / 教师 / 年 | 按席 | 同左（可略高含 SLA） |
| 含内 token | 按校打包 | 同左或略高 |
| 超额 token | 单价 A | 单价 A（模型同价） |
| SLA | 工作日 | 更高 / 独立故障域 |
| BYOK | 可选加价 | 常含或易开 |

**内部成本锚：**

- Dedicated 年费 **≥** 该 VM/主机 + 运维摊销 + 余量  
- 含内 token **≤** 采购价的安全线（建议按 P95 校用量设包）  
- 席位费覆盖支持与迭代，不靠 token 赌利润  

### 3.4 谁付模型钱

| 模式 | 含义 | 建议 |
|------|------|------|
| 平台代付 | 你买 Kimi，再卖给学校 | 默认 Standard；简单 |
| 校级 BYOK | 学校自己的 Key，你收平台费 | Dedicated/敏感校 |
| 混合 | 默认模型走平台；校可挂自有 Key | 长期最灵活 |

**决策建议：** Standard = 平台代付 + 计量；Dedicated = 代付或 BYOK 二选一写进合同。

## 4. 和「一校一机 + 用户是租户」对齐的收费

```text
部署叙事：一校一环境（可选）
收费叙事：按校开通 + 按教师席位 + 按 AI 用量
不要：按虚拟机台数向老师收费
```

- **学校** 是付费主体（或教育局/集团）  
- **教师** 是被授权使用者（席位）  
- **机器** 是你的成本项，可折进 Dedicated 价，**不是**给老师的 SKU

## 5. 运营动作清单（10 校）

| 周期 | 动作 |
|------|------|
| 开通 | 建 `school_id`、席位上限、部署档、包量、管理员 |
| 每日 | 错误率、延迟、token 突刺、跨校 deny |
| 每周 | 各校用量 TOP、即将超额预警 |
| 每月 | 账单、续约风险、版本与安全补丁 |
| 变更 | 功能开关按校；镜像舰队发布 |

**配额建议字段（实现时落库/配置）：**

- `school_id`  
- `plan`: standard \| dedicated  
- `seat_limit`  
- `token_quota_monthly`  
- `token_used_monthly`  
- `hard_limit_action`: block \| degrade \| notify_only  
- `model_allowlist`  
- `byok_enabled`

## 8. 一句话结论（讨论锚点）

- **部署：** 学校是隔离与（可选）专属机器的边界；教师是校内租户，不是机器。  
- **收费：** 校费 + 席位 + token（包量内含）；专属部署另加固定价；模型成本必须可转嫁或可限额。  
- **10×100：** 优先同一产品、两种部署档、一套计量，而不是 1000 套环境。
